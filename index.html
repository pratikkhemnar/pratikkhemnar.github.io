// troubleshooting playbook
“The website is down.” My first 7 checks


A repeatable order beats guessing. This is how I narrow down a failing Apache site on RHEL.


Client→DNS→Firewall→Apache (httpd)→App / files→Database




Is the service up?
Confirm httpd is running and enabled.
systemctl status httpd


Read the logs
Errors usually say exactly what failed.
journalctl -u httpd -xe
tail /var/log/httpd/error_log


Validate config
Catch syntax errors before restarting.
httpd -t


Ports & firewall
Is it listening, and is traffic allowed?
ss -tulnp | grep :80
firewall-cmd --list-all


Permissions
Check ownership and mode of the web root.
ls -ld /var/www/html


Disk space
A full filesystem breaks logging and uploads.
df -h; lsblk


Reachability
Test locally, then from outside.
curl -I http://localhost







// hands-on labs
Apache on RHEL


I installed and configured Apache (httpd) on RHEL and deployed static HTML/CSS pages under /var/www/html. A typical setup:


# install, enable and start
sudo dnf install -y httpd
sudo systemctl enable --now httpd

# /etc/httpd/conf.d/site.conf  (example virtual host)
<VirtualHost *:80>
    ServerName example.local
    DocumentRoot /var/www/html
    ErrorLog  /var/log/httpd/site-error.log
    CustomLog /var/log/httpd/site-access.log combined
</VirtualHost>

# validate, allow traffic, reload
sudo httpd -t
sudo firewall-cmd --permanent --add-service=http && sudo firewall-cmd --reload
sudo systemctl reload httpd
